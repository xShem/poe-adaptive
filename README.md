# PoE Adaptive 0.1.0

Первая тестовая версия аналога [PoeRedux](https://github.com/Gineticus/PoeRedux)
для **Path of Exile 1 и Path of Exile 2 в Steam**, Windows x64.
Интерфейс и самостоятельный исполняемый файл на .NET 10 / WPF.

Перенесены все 13 функций оригинала для PoE 1 и все 15 для PoE 2:
камера, миникарта, цвета модификаторов, HP монстров, туман, частицы окружения,
тени, свет, Delirium, частицы, эффекты и экспериментальный Black Screen;
также трупы для PoE 1 и туман Атласа, дождь и облака для PoE 2.
Black Screen оставлен экспериментальным, как у оригинала.

**Наличие функции в списке означает перенос её исходного правила.
Совместимость и результат в актуальных клиентах игры ещё требуют проверки.**

## Как работает адаптация

- Приложение находит библиотеки Steam и установки обеих игр, читает `buildid`.
- При каждом анализе заново строит дерево ресурсов и создаёт новые экземпляры
  правил. Новые файлы внутри известных каталогов попадают в сканирование.
- Профиль собирается от исходного индекса именно этой Steam-сборки; снятая
  функция не переносится из предыдущего профиля.
- Преобразования сначала выполняются в отдельном каталоге. Анализ не пишет
  в установку игры. Отчёт показывает число действительно изменённых файлов.
- Если хотя бы одна выбранная функция не дала изменений, применение всего
  плана блокируется. Причиной может быть новый формат, отсутствие нужного
  ресурса, отключённые цвета или перекрытие другой функцией.
- Перед записью проверяются сборка, контрольная сумма индекса и закрытая игра.
- Новые bundles копируются в уникальный каталог `Bundles2/PoeAdaptive/…`.
  Готовый индекс переключается атомарно после копирования и проверки файлов.
- Исходный индекс хранится отдельно для каждой установки и Steam-сборки.
  Журнал позволяет распознать прерванное переключение при следующей операции.
- После успешного ручного применения сохраняется профиль. С включённым
  автоприменением открытое приложение проверяет Steam каждые 20 секунд.
  Для новой сборки оно заново строит и проверяет план перед применением.
  При ошибке останавливается; повторную проверку запускают вручную.

Автоматизация рассчитана на обновления, сохраняющие известную структуру
ресурсов. Счётчик изменений **не доказывает правильность поведения в игре**.
Если разработчики переименовали смысловые поля, изменили формат архивов или
логику шейдеров, понадобятся новые правила либо новая версия библиотеки.
Программа не умеет самостоятельно изобретать и проверять такие замены.

## Первый запуск

1. Распакуйте Windows-архив целиком и запустите `PoeAdaptive.exe`.
2. Если клиент ранее изменяли PoeRedux или другим патчером, сначала выполните
   проверку целостности файлов в Steam. Первая база должна быть исходной.
3. Завершите обновление Steam и закройте обе игры.
4. Нажмите «Найти в Steam». Для ручного выбора нужен файл
   `<папка игры>/Bundles2/_.index.bin`.
5. Выберите функции, настройте камеру и цвета, нажмите «Анализ».
6. Посмотрите отчёт. Функции с нулём изменений снимите и повторите анализ;
   у пересекающихся функций это может быть ожидаемым результатом.
7. Нажмите «Применить». Сохранённый профиль можно автоматически повторять
   после смены Steam-сборки, пока приложение открыто.

Понадобится совместимая **64-битная Oodle DLL**. Приложение ищет
`oo2core*.dll` в корне выбранной игры, затем `oo2core.dll` рядом с EXE.
Если библиотека не найдена, анализ остановится с сообщением. Используйте
совместимую библиотеку из своей локальной установки игры либо уже
используемого экземпляра PoeRedux; в этот архив она не включена.

Для отключения всех изменений используйте «Восстановить». Оно возвращает
исходный индекс текущей сборки и выключает автоприменение этого профиля.
Копии других сборок не используются. Неиспользуемые дополнительные bundles
сохраняются; официальная проверка файлов Steam остаётся способом восстановления
при повреждении ресурсов. Если Steam восстановил точный исходный индекс той
же сборки, следующий анализ распознает это автоматически.

## Правила без пересборки

Кнопка «Данные» открывает `%LOCALAPPDATA%/PoeAdaptive/`:

| Каталог / файл | Содержимое |
| --- | --- |
| `Backups/<установка>/<buildid>/` | Исходный индекс, контрольные суммы, журнал |
| `Profiles/` | Выбранные функции, камера, цвета, режим автоприменения |
| `Reports/` | Последний JSON-отчёт по каждой установке |
| `Staging/` | Временно подготовленные ресурсы |
| `rules.json` | Необязательные локальные правила замены |

Чтобы переопределить функцию, скопируйте `rules.example.json` в этот каталог
как `rules.json` и задайте проверенные шаблоны. Пример заменяет правило дождя
PoE 2, учитывая пробелы вокруг `:` и разные формы числа. Функция всё равно
должна быть выбрана в интерфейсе. Правила с совпавшими `AppId` и `PatchId`
полностью заменяют встроенную реализацию этой функции; несколько правил
выполняются последовательно. Все правила перечитываются при новом анализе.

Поля `PathPrefix` и `Extension` ограничивают ресурсы; `Pattern` — регулярное
выражение .NET, `Replacement` — замена .NET с поддержкой `$1` / `${1}`.
`MinMatches` и `MaxMatches` задают допустимое суммарное число совпадений.
Выход за границы отменяет весь план. Тайм-аут выражения — 2 секунды на файл.
Кодировки: `utf-16` для большинства metadata, `ascii` для HLSL, `utf-8`.
Список `PatchId` соответствует именам классов в `Patches/` и `Patches2/`.
`238960` — PoE 1, `2694490` — PoE 2.

Автоматического скачивания или генерации новых правил в версии 0.1.0 нет.

## Сборка и проверки

На машине с .NET 10 SDK:

```powershell
dotnet build PoeRedux.slnx -c Release
dotnet run --project PoeAdaptive.Tests -c Release
dotnet publish PoeRedux/PoeRedux.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
```

Ядро и тесты работают также на Linux. GUI запускается на Windows.
`PoeAdaptive.Core` содержит Steam VDF, контрольные суммы, журнал и публикацию.
`PoeAdaptive.Engine` компилирует правила и анализатор из папки `PoeRedux`.
`PoeRedux` содержит WPF-интерфейс и исходные преобразования оригинала.
В GitHub Actions настроены сборка, проверки, запуск главного окна Windows-приложения
и Windows-артефакт.

Для выпуска пакета вручную запустите **Publish tested Windows release** в Actions:
укажите ID успешного запуска **Build and test** и тег версии. Задача берёт его
Windows-артефакт, прикладывает исходники ровно того же коммита и SHA-256, затем
публикует предварительный релиз. Уже опубликованные версии не перезаписываются.

20 проверок используют искусственные ресурсы и временную Steam-установку:
смена сборки, исходные копии, атомарная запись, восстановление журнала,
блокировка устаревших планов и преобразования ресурсов. Они не проверяют
нативную Oodle DLL, отображение WPF или поведение текущей игры.

Для следующего этапа проверки запустите анализ на обеих установках и сохраните
отчёты из `Reports/`. Они содержат buildid и результаты функций, но не сами
ресурсы игры. Пути к установке/компьютеру в публикуемый отчёт не записываются.

Лицензии, источники и версии зависимостей перечислены в `THIRD_PARTY.md`.
