# Работа с установленными играми

## Выбор установки

«Найти игры» объединяет Steam, реестр GGG и манифесты Epic. Каждая строка
содержит игру, клиент и каталог. «Каталог…» выбирает корень установки;
«Файл…» принимает внешний индекс или GGPK, проверяя содержимое.
При двух кандидатах в одном каталоге выберите конкретный ресурс.
Epic должен иметь действующий манифест, GGG — распознаваемые метаданные EXE.
Неизвестная игра или противоречие между EXE и манифестом блокируют работу.

Если установка не обнаружилась, запустите диагностику, описанную ниже.
Не переименовывайте PoE 1 в PoE 2 для обхода проверки.

## Анализ и применение

Выполните официальную проверку файлов перед созданием первой базы,
особенно после другого патчера. Дождитесь завершения загрузки/проверки.
Закройте игру. Сам по себе запущенный Steam / Epic не блокирует операцию:
проверяются статус установки, маркеры обновления и доступ к файлам.
Процесс отдельного клиента GGG может совмещать игру и лаунчер; если его
состояние не удаётся подтвердить, закройте его перед операцией.

Для GGPK в интерфейсе заранее показывается консервативный резерв:
четыре размера контейнера плюс 1 ГиБ. Резерв учитывает исходную копию,
подготовку, дополнительные bundles и временный файл замены. Это предварительная
оценка; перед копированием проверяются фактические размеры и свободное место
на соответствующих томах. На томе игры для применения требуется место под
целый подготовленный контейнер. Большие контейнеры и их полные SHA-256
обрабатываются долго; 20-секундный опрос не хеширует весь GGPK.

Анализ открывает исходные ресурсы только для чтения и записывает результаты
в `%LOCALAPPDATA%/PoeAdaptive`. Отдельный исходный полный GGPK сохраняется
для восстановления; преобразования выполняются в staging, затем собирается
и проверяется отдельный контейнер. Внешние bundles создаются в уникальном
`Bundles2/PoeAdaptive/<сеанс>/`. Исходный индекс переключается после проверки.

Каждая выбранная функция должна дать реальные изменения. Ноль означает
неопределённый результат; снимите функцию либо исправьте правило и повторите
анализ. Наличие изменений не подтверждает правильность поведения в игре.
Перед применением повторно проверяются версия, отпечатки, план, файлы,
место, игра и обновление клиента. Устаревший план блокируется.

## Восстановление и сбой

«Восстановить» использует только исходную копию текущей игры, установки,
клиента и версии. Для GGPK возвращается полный исходный контейнер побайтово;
для внешних bundles — исходный индекс. Дополнительные неиспользуемые bundles
не удаляются. Копия другой версии не используется.

Запись ведётся через файл на том же томе и `File.Replace`; оригинал хранится
отдельно. Журнал перед переключением содержит ожидаемые хеши до/после.
После сбоя распознаются оба известных результата; неизвестный результат
останавливает дальнейшую запись. Сохраните данные и выполните официальную
проверку файлов клиента; не удаляйте журналы для обхода блокировки.

## Обновления

Steam использует buildid. Epic — AppVersionString и отпечаток ресурсов.
GGG — содержимое EXE и отпечаток ресурсов. Собственная запись фиксируется
в паспорте версии и не считается обновлением. Размер, время и небольшие
выборки начала/конца запускают углублённую проверку при изменении.

Если ресурсы изменились, а независимый признак лаунчера/EXE не изменился,
программа не может доказать происхождение изменения: автоприменение
останавливается. Это относится и к легитимному обновлению GGG, которое не
меняет EXE. Для такого случая завершите официальную проверку файлов и нажмите «После проверки».
Команда требует вашего подтверждения, сохраняет историю паспорта/журнала, принимает
текущие ресурсы как исходные и требует нового анализа. Это доверие вашему
подтверждению, а не автоматическое доказательство происхождения файлов.
Автоматическая совместимость неизвестного изменения не заявляется.
Автоприменение строит новый план и проверяет правила. При несовместимости
останавливается; исправление будущих форматов автоматически не генерируется.

## Данные 0.1.0

Steam-ключ установки остаётся прежним. Исходные `Profiles/<key>.json`,
`Backups/<key>/<buildid>/original.index.bin`, `state.json` и `pending.json`
читаются. Новый профиль содержит SchemaVersion=2 и привязку к установке.
Перед заменой старого профиля сохраняется `.v0.1.0`.

Старый массив `rules.json` читается, AppId 238960 сопоставляется PoE1,
2694490 — PoE2; проверенный вариант сохраняется рядом как `rules.json.v2.json`.
Исходный файл не перезаписывается. Новый формат: `SchemaVersion: 2`, `Rules`,
у правила `Game: 1` или `2`; legacy `AppId` может быть пустой строкой.
Неизвестный AppId, противоречие игры или неизвестная схема блокируются.

## Минимальная диагностика

Из Windows-пакета:

```powershell
.\PoeAdaptive.Diagnostics.exe 'D:\Игры\Path of Exile 2\Content.ggpk' "$env:USERPROFILE\Desktop\poe-report.json"
```

Можно выбрать каталог либо внешний индекс. Диагностика открывает ресурсы
на чтение, проверяет структуру и один раз вычисляет полный SHA-256.
JSON содержит формат, размер, распознанную игру/клиент, версию лаунчера и
метаданные EXE, без пути установки и содержимого игровых ресурсов.
Сохраните также `Reports/<key>-latest.json` после анализа. Для проверки
настоящего клиента достаточно этих отчётов, версии игры и описания результата;
полный многогигабайтный GGPK передавать не требуется.
