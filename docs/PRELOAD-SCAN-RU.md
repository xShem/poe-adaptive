# Отдельная программа для предзагрузки PoE: GGPK PreloadScan

**PoeAdaptive.PreloadScan.exe** — автономная утилита Windows x64. Она не требует установленного Steam и не требует `Bundles2/_.index.bin`. Она **ничего не меняет в GGPK**. Её назначение — выяснить, встречаются ли в доступных обычных файлах предзагрузки имена, фрагменты кода и пути, с которыми работают функции PoE Adaptive.

## Как запустить

1. Закройте игру и дождитесь завершения предзагрузки. Скачайте `PoeAdaptive-PreloadScan-0.1.0-win-x64.zip` из отдельного тестового релиза GitHub.
2. Распакуйте ZIP в любую папку **вне каталога игры**.
3. Перетащите `Content.ggpk` на `PoeAdaptive.PreloadScan.exe` или запустите из PowerShell:

```powershell
.\PoeAdaptive.PreloadScan.exe "D:\Games\Path of Exile\Content.ggpk"
```

4. После выполнения появится JSON на рабочем столе с именем `PoE-GGPK-preload-report-*.json`. При необходимости второй аргумент задаёт точный путь для JSON (вне каталога игры). Пришлите **только JSON**, не весь архив.

## Что проверяется

Наличие путей и текстовых признаков для Camera, MonsterHP, Corpse, Minimap, ColorMods (PoE 1), ColorMods2 (PoE 2), Fog, Shadow, Light, EnvironmentParticles, Rain, Clouds, AtlasFog, Delirium, Particles, Effects, BlackScreen. Используются эвристики из исходников `PoeRedux/Patches` и `Patches2`. Программа обнаруживает GGPK v3 и v4 и сканирует каталог записи, даже если `Bundles2/_.index.bin` отсутствует.

В JSON различаются:
- `text-indicators-found` — найден указанный фрагмент текста в доступном файле. Это свидетельство наличия фрагмента, **не** работы патча.
- `path-candidates-only` — похоже название/расположение файла, но содержимое не подтвердило признак.
- `no-evidence-in-scanned-direct-files` — сканирование ничего не показало; **не означает отсутствия кода в файле предзагрузки**.
- `Truncated` и `Warnings` — ограничения просмотра и причины, по которым результат не является полным.

По умолчанию сканируются не более 100 000 записей каталога, 512 обычных текстовых файлов, первые 256 КиБ каждого файла, до 24 МиБ суммарного чтения. Отчёт включает только относительные внутренние пути, короткие текстовые фрагменты, счётчики и предупреждения. **Не включает** абсолютный путь к вашей игре, EXE, полный GGPK или большие игровые данные. Отправка отчёта автоматом отсутствует.

## Что сканер не умеет

Если будущая лига предзагружена внутри **сжатых** `Bundles2`, код может быть недоступен обычному просмотру без декомпрессии индекса и bundles. Этот маленький сканер **не использует Oodle** и не распаковывает bundles. Результат «не найдено» не является доказательством отсутствия реализации функции в предзагрузке. Он также не заявляет поддержку патчинга GGPK v4 и других неподтверждённых форматов.

## Сборка из исходников

Используется закреплённый SDK .NET 10 из `global.json`. Пример:

```powershell
dotnet publish PoeAdaptive.PreloadScan/PoeAdaptive.PreloadScan.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

Консольные синтетические тесты находятся в `PoeAdaptive.Tests/AdditionalChecks.cs`. Они **не проверяют** реальный игровой клиент и готовность функций будущей лиги.
