# Отдельная программа для предзагрузки PoE: GGPK PreloadScan

**PoeAdaptive.PreloadScan.exe** — автономная утилита Windows x64. Она не требует установленного Steam и не требует `Bundles2/_.index.bin`. Она **ничего не меняет в GGPK**. Её назначение — выяснить, встречаются ли в доступных обычных файлах предзагрузки имена, фрагменты кода и пути, с которыми работают функции PoE Adaptive.

## Как запустить

1. Закройте игру и дождитесь завершения предзагрузки. Скачайте `PoeAdaptive-PreloadScan-0.2.1-win-x64.zip` из отдельного тестового релиза GitHub.
2. Распакуйте ZIP в любую папку **вне каталога игры**.
3. Перетащите `Content.ggpk` на `PoeAdaptive.PreloadScan.exe` или запустите из PowerShell:

```powershell
.\PoeAdaptive.PreloadScan.exe "D:\Games\Path of Exile\Content.ggpk"
```

4. После выполнения появится JSON на рабочем столе с именем `PoE-GGPK-preload-report-*.json`. При необходимости второй аргумент задаёт точный путь для JSON (вне каталога игры). Пришлите **только JSON**, не весь архив.

## Что проверяется

Наличие путей и текстовых признаков для Camera, MonsterHP, Corpse, Minimap, ColorMods (PoE 1), ColorMods2 (PoE 2), Fog, Shadow, Light, EnvironmentParticles, Rain, Clouds, AtlasFog, Delirium, Particles, Effects, BlackScreen. Используются эвристики из исходников `PoeRedux/Patches` и `Patches2`. Программа обнаруживает GGPK v3 и v4 и сканирует каталог записи, даже если `Bundles2/_.index.bin` отсутствует.

В JSON различаются:
- `text-indicators-found` — найден указанный фрагмент текста в доступном файле. Это свидетельство наличия фрагмента, **не** работы патча.
- `path-candidates-only` — похоже название/расположение файла, но содержимое не подтвердило признак.
- `no-evidence-in-scanned-direct-files` — сканирование ничего не показало; **не означает отсутствия кода в файле предзагрузки**.
- `Truncated` и `Warnings` — ограничения просмотра и причины, по которым результат не является полным.

По умолчанию сканируются не более 100 000 записей каталога, 512 обычных текстовых файлов, первые 256 КиБ каждого файла, до 24 МиБ суммарного чтения. Отчёт включает только относительные внутренние пути, короткие текстовые фрагменты, счётчики и предупреждения. **Не включает** абсолютный путь к вашей игре, EXE, полный GGPK или большие игровые данные. Отправка отчёта автоматом отсутствует.

## Что сканер не умеет

Если будущая лига предзагружена внутри **сжатых** `Bundles2`, код может быть недоступен обычному просмотру без декомпрессии индекса и bundles. Этот маленький сканер **не использует Oodle** и не распаковывает bundles. Результат «не найдено» не является доказательством отсутствия реализации функции в предзагрузке. Он также не заявляет поддержку патчинга GGPK v4 и других неподтверждённых форматов.

## Сборка из исходников

Используется закреплённый SDK .NET 10 из `global.json`. Пример:

```powershell
dotnet publish PoeAdaptive.PreloadScan/PoeAdaptive.PreloadScan.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

Консольные синтетические тесты находятся в `PoeAdaptive.Tests/AdditionalChecks.cs`. Они **не проверяют** реальный игровой клиент и готовность функций будущей лиги.

## Дополнение 0.1.1 по предзагрузке

После отчёта со сканированием 53 204 файлов, но нулевым количеством прочитанных текстовых файлов, добавлены `FileTypes`, `RootGroups`, `BundleFilesFound`, `TextFileCandidates` и `IndexCandidates`. Исправлена ошибка: имена `cachedhlslshaders/dx12.bundle.bin` и аналогичные больше не считаются свидетельством кода функции BlackScreen. Отсутствие `_.index.bin` не означает, что архив повреждён или что в нём нет ресурсов лиги.

## Версия 0.2.1 — глубокая проверка предзагрузки PoE 1 с Oodle

**Что нужно:** официальный PoE 1 с GGPK и **ровно один** совместимый файл \`oo2core.dll\` или \`oo2core_*.dll\`, который пользователь помещает **в ту же папку, что и \`PoeAdaptive.PreloadScan.exe\`**. Мы не включаем, не распространяем и не скачиваем эту библиотеку.

Сканирование запускается простым перетаскиванием \`Content.ggpk\` на EXE. Утилита сначала собирает прежний отчёт по прямым файлам, затем пытается загрузить Oodle **только из каталога EXE**, проверяет наличие нужных экспортируемых функций и читает ограниченную выборку сжатых \`*.bundle.bin\`. Если DLL отсутствует, основной JSON всё равно создаётся, а поле \`DeepBundles.Status\` содержит \`oodle-unavailable\` и объяснение.

В JSON добавлено независимое поле \`DeepBundles\` со статусом, хешем локальной DLL, количеством найденных и прочитанных bundles, числом распакованных блоков, предупреждениями, а также смещениями и признаками для 13 функций PoE 1. Раздел \`Features\` основного отчёта по-прежнему относится **только к прямым файлам**.

В целях безопасности действует ограничение: не более 128 выбранных bundles, 2 блоков из каждого, 64 МиБ распакованных данных суммарно. Перед распаковкой проверяется заголовок, размеры и таблица блоков. Исходный GGPK открывается исключительно с \`FileAccess.Read\`; полные bundles, DLL и абсолютные пути игры в JSON не сохраняются. Никаких файлов игры программа не изменяет.

**Ограничения:** это не полноценный экстрактор GGPK. При отсутствии \`Bundles2/_.index.bin\` виртуальные пути и границы отдельных ресурсов неизвестны. Даже если найден \`CreateCameraZoomNode\` или \`walkable_color\`, это только свидетельство в распакованном блоке, не гарантия работоспособности патча. Поиск не охватывает все 74 ГБ, поэтому отсутствие признака не доказывает его отсутствия в остальных блоках. Для тестов в CI настоящая DLL Oodle не применяется — на реальном клиенте нужна отдельная проверка.

## Уточнение по реальному отчёту предзагрузки PoE 1

В отчёте от 13 ноября 2026 года 128 из 48 218 bundles декодированы без ошибок (245 блоков, 61 615 643 байта). Старое диагностическое правило посчитало 26 совпадений Delirium по общей строке `Metadata/Effects/Environment` из `terrain.bundle.bin`, включая пути снежных и погодных эффектов. Это **ложное подтверждение Delirium**: реальный патч работает с `metadata/effects/environment/league_affliction`, поэтому правило теперь требует специфическую строку `league_affliction` или `LeagueAffliction`. Ноль совпадений у остальных функций при такой ограниченной выборке не позволяет делать вывод об их отсутствии.
